# Единый вес, 27 сентября 2026

Фильтрация выполняется на Pi: усечённое среднее 8 чтений АЦП (прежнее), медиана 5 измерений, EMA 0.2; при отклонении медианы от EMA ≥60 кг — коэффициент 0.65. Рабочий вес округляется до 5 кг, половины от нуля. Для переключения соседних значений нужен выход на 3.5 кг от текущего показания (гистерезис 1 кг сверх границы округления). Внутреннее EMA не округляется.

`weight`, `scale_measurement.weightKg`, LAN и панель используют этот вес. Снимок телеметрии берётся единожды, чтобы идентификатор и вес не относились к соседним измерениям. `raw` остаётся диагностическим весом в кг до медианы/EMA, без округления; это не отдельные коды АЦП. Нетто панели по-прежнему локальное: при включённом нетто абсолютное значение отличается от общего веса намеренно.

Сервер для scale_measurement не применяет вторую калибровку и realtime-фильтр. Невалидный canonical-пакет не подменяется сырьём. Старый серверный фильтр оставлен только для устройств без scale_measurement. Исторические записи не переписывались.

## Проверка архива

Источник: read-only SQLite `/opt/backups/farm-site/weight-analysis-20260824_091500/server-dev.db`; Hozain_01, UTC 22–24 августа. Выгрузка 101157 строк, SHA256 CSV `052a30b7da1c1535a6577ff42e4e4f46659d41ef36b051e2d543ab1bad6427ee`. Приватный CSV хранится вне Git. Частота архива: медиана интервала 2 с, не нынешние 0.5 с. Индивидуальных кодов АЦП в этих пакетах нет.

`python compare-weight-filters.py <csv>` воспроизводит сравнение. Общий диапазон сравнения −1000…8000 кг, сброс после разрыва >4 с; это ограничения сравнительного стенда, не новые пределы прибора. Из непересекающихся минутных блоков выбраны 33 с минимум 20 отсчётами и расхождением медиан трёх третей ≤10 кг. Первые 10 отсчётов каждого блока исключены из оценки разброса. Это автоматические кандидаты стабильных участков, без эталонного веса: разброс не является погрешностью весов.

| Фильтр | Медиана размаха P95−P05, кг | P90 размаха по блокам, кг |
|---|---:|---:|
| Прежний Pi: median3, EMA .5/.8, порог30 | 115 | 185 |
| Прежний сайт: Hampel9, median7, EMA .1/.8, порог180 | 20 | 40 |
| Новый Pi: median5, EMA .2/.65, порог60 | 35 | 95 |

Новый фильтр уменьшает типичный разброс примерно на 70%, но не гарантирует неподвижных цифр в вибрирующей машине. По отдельным дням медианы размаха 40/25/55 кг. Серверная модель здесь непрерывная, без повторного старта на каждом 40-пакетном окне HTTP current; таблица сравнивает алгоритмы, а не измеренную сетевую задержку сайта.

Отдельный синтетический тест постоянного скачка при 2 Гц: достижение 90% скачка 25/100/500 кг новым фильтром за 7/3.5/2 с, прежним серверным за 14/13/7 с. Это тест отклика, не скорость, измеренная на Хозяине. Результаты архива не интерполировались до 2 Гц. Калибровка и проверка под реальной нагрузкой обязательны для оценки точности новой установки.

## Установка на Pi

Доступ к Pi во время подготовки отсутствовал. После появления сети:

```bash
cd /opt/host-monitor
git pull --ff-only origin with-tablet
sudo systemctl stop host-monitor
sudo .venv/bin/python apply-weight-filter.py
sudo systemctl start host-monitor
sudo systemctl status host-monitor --no-pager
sudo journalctl -u host-monitor -n 30 --no-pager
```

Скрипт меняет только 5 параметров фильтра и сохраняет резервную копию config. Калибровка, PIN, сеть, очередь, разрешение панели остаются прежними. Если применение параметров завершилось ошибкой, запустить сервис с сохранённым config и сообщить вывод. После успешной установки проверить валидные веса: кратны 5, `weight == scale_measurement.weightKg`, одинаковые packetId/time через LAN и сервер; при выключенном нетто панель показывает тот же вес. При отсутствии датчиков/калибровки valid=false нормально.

27 сентября пользователь включил панель, разрешил system-site-packages в venv для gpiozero и подтвердил работу кнопок/меню. Прежняя запись «панель выключена» в отчёте 26 сентября относится к первоначальной установке.
