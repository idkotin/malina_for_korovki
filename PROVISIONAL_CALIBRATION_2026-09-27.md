# Временная калибровка по явному поручению пользователя

Пользователь попросил запустить систему на имеющихся данных сейчас, продолжить исправление позже. Обычная span-калибровка не прошла проверку отношения изменения сигнала к размаху шума; эту проверку в основном коде не отключали.

Отдельный apply-provisional-calibration.py записывает временный коэффициент по принятому zero 2745.8333333333335 (12:55:30) и последнему stationary span 4732.5 (13:48:37), известная масса 4015 кг со штатного терминала. Пользователь подтвердил реальный лежащий груз и выключенную мешалку в последнем замере. scale=2.0209731543624163 кг/отсчёт. Размах 334.166667 соответствует примерно 675 кг до фильтрации. Это НЕ подтверждённая точность; шаг экрана 5 кг не меняет этого.

Скрипт сохраняет предыдущий файл рядом, атомарно записывает новый с provisional=true и precision_verified=false. confirmed=true разрешает выдачу рабочего веса и использование в заданиях по явному запросу пользователя; существующий клиент не показывает специальную метку provisional. Калибровочный ID меняется; задания, начатые с иной калибровкой, несовместимы. Настройки фильтра, сети, GPIO и очередь не меняются. Нет обращения к АЦП. Запускать только с остановленным host-monitor из /opt/host-monitor. После установки не выполнять zero/span заново до дальнейшей диагностики; этот файл переживает перезагрузку.

Локальная проверка в изолированном временном каталоге: существующий файл сохранён без изменений в backup, offset отображается в 0, loaded — в 4015 кг через штатный загрузчик калибровки. На Pi устанавливает пользователь; результат ещё не подтверждён.

Далее: проверка тракта/настроек АЦП, калибровка на неподвижных пустом/нагруженном смесителе, контроль известной нагрузкой и нулём. Для отката остановить сервис, вернуть конкретный файл .before-provisional-* на calibration_path и запустить сервис; не выбирать резервную копию наугад.
